# Редактор электрических схем для Arduino и ESP32

Курсовой проект: десктопный редактор электрических схем с футуристичным интерфейсом, встроенным редактором кода, конструктором микросхем, симуляцией и 3D-видом.

## Порядок работы

- Работать строго по этапам, которые пользователь присылает по одному. Не реализовывать будущие этапы.
- После каждого этапа: сборка без ошибок и предупреждений, успешные тесты, краткий отчёт и инструкция ручной проверки.
- После каждого этапа дополнять этот файл списком выполненного; выводить дерево исходных файлов и подтверждать соблюдение архитектурных правил.
- Подготовка и этап 1 завершены. Ждать следующий этап пользователя; будущую функциональность самостоятельно не реализовывать.

## Обязательный стек

- Только C# 12, .NET 8, WPF. XAML — только разметка и стили.
- MVVM: CommunityToolkit.Mvvm. DI: Microsoft.Extensions.DependencyInjection.
- Редактор кода: AvalonEdit (ICSharpCode.AvalonEdit).
- 3D: HelixToolkit.Wpf; актуальную версию проверять в NuGet. Все модели строить процедурно из примитивов, внешние модели запрещены.
- Скрипты микросхем: Microsoft.CodeAnalysis.CSharp.Scripting.
- JSON: System.Text.Json. Тесты: xUnit.

## Решение и строгая архитектура

- CircuitEditor.Core: модели, валидация, расчёты; без зависимости от UI, WPF, System.Windows и ViewModels. Проверять ссылки в csproj.
- CircuitEditor.Simulation: движок симуляции, зависит от Core.
- CircuitEditor.App: WPF, ViewModels, Views; зависит от Core и Simulation.
- CircuitEditor.Tests: тесты Core и Simulation на xUnit.
- Один класс = один файл. Файл не длиннее примерно 450 строк, иначе разбивать. Не помещать несколько классов в один файл.
- Строгий MVVM. View (XAML) не содержит логики. Code-behind пустой или только InitializeComponent; допустима лишь передача события мыши в команду ViewModel.
- ViewModel не создаёт View, не использует MessageBox/Dispatcher напрямую. Взаимодействие с UI — через интерфейсы сервисов, например IDialogService.
- Каждый новый сервис имеет интерфейс и регистрируется в DI.
- Публичные классы Core имеют XML-комментарии. Без магических чисел. Ошибки обрабатываются без падения приложения.

## Визуальный стиль для будущих этапов

- Sci-fi HUD; фон #0A0E17.
- Неон: циан #00E5FF, фиолетовый #8B5CFF, зелёный #39FF88, красный #FF3B5C.
- Свечение через DropShadowEffect; полупрозрачные панели со скруглением и тонкой светящейся рамкой; плавные анимации.
- Моноширинный шрифт для чисел и кода; векторные иконки.
- Кастомное окно через WindowChrome. Ни одного стандартного Windows-контрола без переопределённого стиля.
- Темы: Neon Dark (по умолчанию) и Light Tech.

### Ручная проверка этапа 1

1. Из корня: dotnet run --project CircuitEditor.App. Ожидается sci-fi оболочка в Neon Dark.
2. Переключить тему списком справа сверху, кнопкой или через Вид → Тема. Панели, текст и рамки меняются без перезапуска.
3. Переключить все четыре вкладки мышью, через меню Вид и Ctrl+1…Ctrl+4. Заголовок и описание центральной заглушки меняются.
4. Выбрать карточку палитры: описание появляется справа, число компонентов схемы остаётся 0.
5. Проверить подсветку мышью и фокус клавишей Tab; открыть меню и список тем, навести на кнопки шапки для подсказок.
6. Перетащить окно за шапку, изменить размер, развернуть и восстановить. В развёрнутом состоянии строка состояния видна над панелью задач.
7. Выполнить dotnet build CircuitEditor.sln -c Release и dotnet test CircuitEditor.sln -c Release.
