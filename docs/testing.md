# Проверки проекта

Сборка и тесты из корня на Windows с SDK, указанным в [global.json](../global.json).

```powershell
dotnet build CircuitEditor.sln
dotnet test CircuitEditor.sln --no-build --no-restore
dotnet run --project tools/UmlGenerator -- . --check
```

Release-проверка прошла с результатом **588/588** в каждом из трёх прогонов. Тесты xUnit охватывают Core, репозитории, Simulation и WPF. Проверки интерфейса используют STA и ресурсы обеих тем. Проверяются девять сохранённых скетчей, маршрутизация к нескольким экземплярам периферии, посадка деталей при переносе, кэш дисплеев, геометрия 3D, переназначение клавиш, миграции и восстановление данных.

Для совместимости отдельно проверены пять `.circ` из предыдущей `main` и 12 файлов `.chip`, экспортированных её программой. Все `.circ` загрузились и прошли проверку цепи. Каждый `.chip` загрузился и повторно экспортировался с исходным SHA-256. Покрытие строк можно измерить через `dotnet test CircuitEditor.sln --collect:"XPlat Code Coverage"`.

| Проект | Строки | Ветвления |
| --- | ---: | ---: |
| Все четыре проекта приложения | 81,71% | 67,68% |
| App | 75,98% | 59,38% |
| Core | 95,40% | 83,89% |
| Infrastructure | 82,36% | 63,76% |
| Simulation | 91,41% | 74,85% |

Бенчмарк с настоящим окном запускается вручную. Порог производительности не проверяется в обычном dotnet test, потому что результаты зависят от дисплея, драйвера и нагрузки. Команды и метрики — в [отчёте производительности](stage-10-performance.md). Изменение физического DPI Windows проверяется по [матрице ручного прогона](ui-audit.md). Модель не сравнивается с аппаратным осциллографом и не претендует на точность электрического стенда.

Если проверка UML завершилась с кодом 1, выполните `dotnet run --project tools/UmlGenerator -- .` и пересоберите изображения по [инструкции](uml/README.md).
