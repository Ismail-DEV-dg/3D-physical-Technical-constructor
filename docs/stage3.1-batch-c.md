# Этап 3.1 — пачка C: датчики и прочее

Все девять оставшихся позиций имеют процедурную векторную модель. В библиотеке 27 компонентов и 0 заглушек. Внешние изображения не используются. Геометрия — в `Infrastructure/Data/footprints.json`, загрузка через существующий репозиторий.

## Корпуса и контакты

| Компонент | Выбранный корпус | Контакты / проверенная вставка |
|---|---|---|
| DHT11 | Синий SIP-4, 12×15,5 мм, решётка | VCC/DATA/NC/GND, 2,54 мм; первый в E5, поворот 90° |
| DHT22 | Белый SIP-4, 15,1×25 мм, решётка | VCC/DATA/NC/GND, 2,54 мм; E5, 90° |
| HC-SR04 | Плата 45×20 мм, два металлических датчика Ø16 мм с сеткой | VCC/TRIG/ECHO/GND; E5, 90° |
| PIR HC-SR501 | Плата 32×24 мм, белая линза Френеля Ø23 мм | VCC/OUT/GND; E5, 90° |
| Фоторезистор | Диск Ø5 мм, извилистая дорожка | Два осевых сформованных вывода; шаг 4–12 отверстий, начальный 6; E5, 90° |
| NTC 10 kΩ | Диск Ø5,5 мм, маркировка 10k | Два осевых сформованных вывода; шаг 4–12, начальный 6; E5, 90° |
| RGB-светодиод | Прозрачный корпус Ø5 мм, статичные R/G/B-кристаллы | R/COM/G/B, второй общий. Сформованные участки ножек разной длины, концы на общем ряду 2,54 мм; E5, 90° |
| Переключатель | Металлический SPDT-корпус 12×6 мм с пазом и движком | A/COM/B; E5, 90° |
| Батарейный блок | Представительный габарит элемента 26×17 мм в плане, красный/тёмный провода | Концы проводов +/− с шагом 2,54 мм вдоль колонки. Первый в A5, 0°; корпус остаётся слева рядом с платой |

DHT NC теперь имеет `Pin.IsExposed=true` и `IsNoConnect=true`: физическая ножка вставляется и занимает отверстие, но внутренней электрической связи нет. Тултип это поясняет. Перемычки не добавлялись; проверка вставки использует все физические ножки, включая NC.

Корпуса — фиксированные учебные варианты; часть ножек сформована под breadboard, а не воспроизводит заводскую сверловку любого клона. RGB показывает разную длину сформованных участков при совместимых концах контактов. Батарейный блок условно представляет выбранное напряжение, не является симуляцией химии элемента.

## Параметры в Core

`Core/Inputs`: ComponentInput, InputDefinition, ComponentInputDefinitions, ComponentInputs. Последний — неизменяемый JSON-снимок только релевантных параметров экземпляра. Изменения проходят через `Component.TrySetInput`: проверяются конечность, границы, допустимые варианты и принадлежность параметра типу компонента. При отказе модель не меняется.

| Тип | Параметры | Начальное значение |
|---|---|---|
| DHT11 (классический четырёхвыводный вариант) | 0…50 °C; 20…90 % RH | 25 °C; 50 % RH |
| DHT22 | −40…80 °C; 0…100 % RH | 25 °C; 50 % RH |
| HC-SR04 | 2…400 см | 100 см |
| HC-SR501 | Нет движения / движение есть | Нет движения |
| LDR | Освещённость 0…100 % | 50 % |
| NTC | −55…125 °C; фиксированный номинал 10 kΩ при 25 °C | 25 °C |
| RGB | Общий катод / общий анод | Общий катод |
| SPDT | A ← COM / COM → B | A |
| Батарея | Только 1,5 / 3 / 3,7 / 4,5 / 5 / 9 В | 9 В |

Форматирование значений/единиц/названий вариантов также в Core. Ползунки имеют собственный WPF ControlTemplate в `InputStyles.xaml`, подключённом единым `Styles.xaml`; штатных Windows-ползунков нет. Дискретные параметры редактируются ComboBox. Нерелевантный свободный ввод номинала и цвет RGB скрыты; у NTC номинал показан отдельно как фиксированный.

Параметры сохраняются в общей модели и проходят JSON round-trip, но файловые команды приложения пока не добавлены. Температура, влажность, движение, расстояние и освещённость не изменяют электрическую модель, значение сопротивления или статичное изображение датчика. Нет симуляции и анимации. При выборе батареи/RGB обновляются подпись экземпляра и рисунок; библиотечное напряжение/описание не переписываются. Положение SPDT меняется только в панели, не кликом по модели; электрическое переключение будет реализовано позже.

## Производительность и проверки

- Кэширование векторных рисунков сохранено. Условия датчиков не вызывают перерисовку статичного холста. Выбор батареи, RGB и SPDT входит в ключ рисунка.
- Повторный Release-замер пяти LCD после прогрева: ≈0,07 мс/13,7 КиБ на подготовку OnRender; обычный hover — 0 изменений Revision на 100 событий. Это не фактический FPS.
- Debug и Release: сборка без ошибок и предупреждений; **233/233 теста**.
- Проверены границы, недопустимые/нечисловые значения, дискретные списки, независимость экземпляров, неизменяемость входного словаря, JSON round-trip всех новых параметров, отсутствие неприменимых ключей.
- Вставка всех девяти моделей: все контакты попадают в разные электрические группы, занятость отклоняется атомарно. У LDR/NTC проверены все допустимые шаги и отказ вне диапазона. Все 27 корпусов сопоставлены с библиотечными выводами; заглушек 0.
- Рендер пачки C проверен при четырёх поворотах и в обеих темах; тултипы всех контактов, включая NC; кэш не обновляется на условиях датчика, но обновляется на батарее/RGB/SPDT. Реальные WPF-привязки ползунков и ComboBox проверены тестами.
- В Release-окне вручную проверены DHT11 и ползунок: температура меняется с 25 до 40 °C, влажность остаётся 50 % RH, корпус не перестраивается и не запускается симуляция.

## Ручная проверка

1. `dotnet run --project CircuitEditor.App -c Release`.
2. Найти DHT11/DHT22, добавить рядом с платой; изменить температуру/влажность ползунками, проверить подписи и ограничения, сменить выделение и вернуться.
3. Для вставки рядовых контактов сначала разместить рядом, повернуть R на 90°, затем совместить первый контакт с E5. Последующие примеры проверять после освобождения отверстий. На NC навести курсор: должна быть легенда о внутреннем отсутствии связи.
4. HC-SR04: расстояние 2…400 см; PIR: движение есть/нет; LDR: 0…100 %, гибкий шаг; NTC: −55…125 °C, фиксированный номинал и гибкий шаг. Внешний вид датчиков не меняется от условий.
5. RGB: сменить общий катод/анод — маркировка общего K/A меняется, R/G/B статичны. SPDT: сменить положение в панели — движок сдвигается. Батарея: выбрать напряжение — обновятся подписи корпуса, инспектора и схемы.
6. Проверить Neon Dark/Light Tech, масштаб и панораму. У параметров датчиков нет кликабельных органов на самих моделях.
