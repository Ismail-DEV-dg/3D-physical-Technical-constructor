# Ошибки, справка и проверка проекта «ку»

По просьбе пользователя перед началом изменений создан коммит `9d6ca01` с завершённым этапом 6. Финальные правки оформляются отдельным коммитом после проверок по дополнительному указанию пользователя. Push не выполняется.

## Что найдено в проекте

Проверены чтением через производственный репозиторий, миграцию и Netlist:

- `[локальный путь удалён]`: сохранённый файл формата 1 от 18.11.2026 22:57. В нём ещё нет поля скетча, поэтому миграция корректно создаёт пустой скетч. Неправильная версия формата не является причиной ошибки маркеров.
- Автосохранение `CircuitEditor/recovery.circ` во временной папке от 19.11.2026 13:12: выбран Uno U1 и вручную написаны setup/loop с pinMode(13, OUTPUT), digitalWrite(13, HIGH). В тексте нет секций `<auto>`.

Ошибка генератора относится к ручному тексту: «Обновить» имеет право заменять только явно отмеченные секции. Связи проводов не могут создать или повредить текстовые маркеры. В сохранённом старом файле пустой скетч генерируется; в проверенном автосохранении генерация раньше отклонялась именно из-за отсутствия секций.

Найдена отдельная электрическая ошибка:

- В текущем автосохранении LED7.anode вставлен в A15, cathode — в B15. По JSON-топологии эти отверстия принадлежат одному узлу. Анод и катод LED7 соединены напрямую.
- R1 подключён отдельно между D13 Uno и GND. LED7 в эту последовательную цепь не входит.
- В старом сохранённом файле аналогично замкнут ещё и LED1: A11/B11. В текущем автосохранении этого компонента уже нет.
- Nano и ESP32 сами по себе не мешают выбору Uno U1. Их свободные выводы питания/земли не считаются ошибкой отсутствующего питания модулей.

Файл «ку.circ» и автосохранение не перезаписывались. Прочитанное состояние не заменялось демонстрационной схемой.

## Как исправить «ку» вручную

1. Сохраните открытый проект, чтобы текущий код и соединения попали в `.circ` версии 2: старый сохранённый файл содержит более раннюю схему без кода.
2. В обновлённом приложении откройте «Код» и нажмите **«Подготовить»**, затем **«Обновить»**. Для простых единственных `void setup()`/`void loop()` будут вставлены пустые секции; существующие инструкции останутся. Подготовка отменяется одним Ctrl+Z.
3. Если секции уже есть, исправьте их по статье `CODE_AUTO_MARKERS`; повреждённые и неоднозначные скетчи автоматически не переписываются.
4. Разместите ножки LED7 в разных несоединённых группах breadboard. A15 и B15 не подходят: A–E одной строки соединены внутри. Группы на разных строках и по разным сторонам центрального канала независимы.
5. Перестройте цепь: **D13 → R1 → анод LED7; катод LED7 → GND**. Не оставляйте резистор отдельной веткой D13 → GND в обход LED.
6. Нажмите «Проверить схему». Предупреждение `LED_SHORT` должно исчезнуть. Проверьте также отсутствие обходного пути LED без последовательного резистора.

Этот этап не исполняет C++: наличие digitalWrite в редакторе пока не включает физическую симуляцию выхода. Это отдельный будущий этап.

## Что изменено в приложении

### Одна панель инструментов

- Слева сохранены компоненты; сверху — «Макет / Схема / Микросхема / 3D / Код».
- Справа теперь только свойства выбранного объекта.
- Внизу одна изменяемая/закрепляемая панель: **«Проблемы / Расчёт DC / Вывод»**.
- Кнопки «Проверить схему», «Рассчитать DC» и флаг напряжений находятся рядом с этими вкладками. Расчёт и его результаты больше не разнесены по нижней и правой панелям.
- «Проблемы» объединяют схему, код и диагностику DC. Есть поиск, источник, уровень, счётчик и переход к месту. Ошибки показываются перед предупреждениями. Результаты DC содержат численные значения; сообщения расчёта доступны в общем списке.
- Изменение размеров, закрепление, скрытие и возврат через «Вид → Панели» сохранены. Старые разрозненные представления списков заменены одним DiagnosticsView.

### Копирование и помощь

- В диалогах ошибок/предупреждений текст доступен для выделения и Ctrl+C; отдельная кнопка копирует сообщение целиком.
- У проблемы есть «Копировать», «Справка», «К месту ошибки». Можно скопировать весь отфильтрованный список. Частичное выделение текста также поддерживается.
- В «Выводе» копируется выбранная строка либо весь вывод, если строка не выбрана.
- При наведении на текст проблемы показываются причина и способ исправления; кнопка в подсказке и кнопка рядом с сообщением открывают соответствующую статью.
- **«Справка → Ошибки и способы исправления»** открывает каталог из 21 статьи. Поиск работает по коду, заголовку, причине, исправлению, компоненту и ключевым словам; можно вставить полное сообщение с кодом. Ctrl+F фокусирует поиск, Esc закрывает окно. Текст статьи можно выделять или копировать целиком.
- Каталог хранится в Infrastructure/Data/error-help.json и читается через IErrorHelpRepository. Буфер обмена и открытие справки изолированы интерфейсами сервисов и зарегистрированы в DI.

### Маркеры и вывод

- Кнопка «Подготовить» появляется для ручного текста без маркеров. AutoRegionInitializer в Core добавляет пустые globals/setup/loop, сохраняя инструкции, комментарии и окончания строк.
- Дубли setup/loop, неполные скобки, уже существующие/повреждённые маркеры приводят к понятному сообщению без изменения исходного текста.
- Генератор выдаёт стабильные коды проблем, а блокирующие ошибки имеют уровень Error. Сообщение об отсутствующих маркерах сразу предлагает «Подготовить».
- Удалён вывод регулярных счётчиков анализа, включая нулевые. Результаты анализа живут в «Проблемах», а не повторяются в консоли. «Вывод» содержит ошибки операций; последовательные одинаковые сообщения не дублируются. Успешная генерация/экспорт сообщаются кратко в самом редакторе.
- Добавлено правило LED_SHORT для общего узла анода и катода LED, в том числе из-за внутреннего соединения отверстий breadboard.

## Проверки

- Unit-тесты подготовки ручного скетча с LF/CRLF, сохранения инструкций и последующей генерации; отказа без изменения текста при неоднозначности.
- Проверки LED_SHORT для A15/B15 и отрицательного случая с разными узлами; различение текстовой ошибки и ошибки соединений.
- Поиск статьи, вставка полного сообщения, копирование диалога/строки/списка/статьи, правильный переход по коду, обработка занятого буфера.
- Отсутствие счётчиков анализа в выводе и подавление одинаковых ошибок.
- Реальное WPF-окно: свойства только справа, три вкладки инструментов снизу, доступное копирование, работающая кнопка статьи внутри подсказки, поиск справки, подготовка маркеров одним Undo/Redo. Визуально проверены Neon Dark и Light Tech.
- Debug: обычные dotnet build / dotnet test — 0 ошибок/предупреждений, 408/408. Release: те же проверки с BaseOutputPath в %TEMP%/CircuitEditor-diagnostics-check — 0 ошибок/предупреждений, 408/408. Работающее пользовательское Release-окно не закрывалось; его файлы остаются заблокированы процессом до закрытия. git diff --check без ошибок.

## Ручная проверка интерфейса

1. Сохранить проект в текущем окне и закрыть старую версию. Из корня запустить `dotnet run --project CircuitEditor.App`.
2. Открыть «ку», перейти в «Код», подготовить маркеры и обновить. Проверить сохранение ручного кода и Ctrl+Z/Ctrl+Y.
3. Внизу открыть «Проблемы», найти `LED_SHORT` или `<auto>`, проверить фильтры и копирование. Вставить скопированное сообщение в поле поиска справки.
4. Навести на проблему и открыть статью. Проверить «Копировать статью», поиск «A15», «маркеры», «GPIO34», а также пустой результат поиска.
5. Нажать «Рассчитать DC»: результаты открываются там же в нижней панели; справа остаются свойства. «Проблемы расчёта» возвращает общий список сообщений.
6. Несколько раз изменить код и дождаться анализа: сообщения «найдено проблем 0» в вывод не добавляются. Ошибки остаются доступными в списке проблем.
7. Проверить Light Tech, изменение высоты панели, закрепление/скрытие и возврат через меню «Вид».

## Архитектура

Один класс на файл, изменённые исходники до 300 строк. Core без WPF/ViewModel. Code-behind новых окон/представлений — только InitializeComponent. Новые сервисы имеют интерфейсы/DI; данные справки читаются репозиторием Infrastructure, не ViewModel. Проекты пользователя не изменяются при диагностическом просмотре. Этап 7 не начинался.
