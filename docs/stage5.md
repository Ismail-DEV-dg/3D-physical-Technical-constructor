## Узлы и отображение

INetlistBuilder соединяет электрические выводы с физическими контактами, контакты с отверстиями, внутренние группы breadboard и концы перемычек. Четыре ножки кнопки соответствуют двум электрическим выводам. Внутренние замыкания кнопки/переключателя/реле и общие земли одной платы задаются electrical.json. Земли разных несоединённых плат автоматически не объединяются.

ID — хеш отсортированных устойчивых терминалов; размещение символа само по себе не меняет ID. Резисторы/LED не объединяют узлы. Имена GND/5V/3V3 — метки, а не дополнительные соединения. Параметры цвета и изгибы проводов не определяют связность.

В «Схеме» ортогональные линии строятся по узлам и не редактируются. Символы перемещаются вручную. PNG/SVG схемы включают эти линии. На время жеста перестроение откладывается; commit, Undo/Redo и открытие проекта обновляют связность.

## ERC

- SUPPLY_SHORT — питание и земля в одном узле.
- LED_NO_RESISTOR — потенциальный путь через одиночный LED либо канал RGB без последовательного ограничения. Параллельный резистор защитой не считается; учитывается ограничение и со стороны анода, и со стороны катода. GPIO рассматривается только как потенциальный участник пути, без утверждения его роли.
- ESP_OVERVOLTAGE — известный источник выше 3.6 В на GPIO ESP32.
- DISCONNECTED_SUPPLY — свободные питающие/земляные выводы модулей и компонентов. Arduino/ESP32 исключены: их питающие выходы могут быть свободны.
- I2C_CONFLICT — одинаковые адреса при общей SDA и общей SCL.
- REQUIRED_PIN — обязательные сигнальные выводы из данных не подключены.
- SOURCE_CONFLICT — разные напряжения источников в одном узле. Есть отдельный тест соединения 5V и 3V3 одной Arduino Uno.
- BATTERY_SHORT — плюс и минус батареи в одном узле без нагрузки.

PinRole и параметры ролей экземпляра подготовлены. PinDirectionRule остаётся заглушкой «этап 6–7»: два выхода вместе, превышение тока GPIO и input-only как выход сейчас не диагностируются. Направление из скетча не угадывается.

«Проверка» поддерживает фильтр серьёзности, иконки, счётчики, ручной запуск и задержку 350 мс после изменения. Выбор строки выделяет компоненты, центрирует активный вид на выводе и подсвечивает его красным/жёлтым.

## Формулы и DC

- Любые две независимые величины U/I/R/P; недоопределённые нулевые пары и неверные единицы дают сообщение.
- Ненагруженный делитель и подбор LED-резистора вверх по E12/E24/E96 с фактическим током и мощностью резистора.
- Прямое и обратное преобразование 4/5 полос с допуском в Core.
- MNA с выбором главного элемента: резисторы; батарея и известные 5V/3V3; одиночный LED и три канала RGB; статические кнопка/переключатель; потенциометр; LDR и NTC.
- LED: включённая ветвь I=(U−Vf)/Rd, выключенная ветвь I=0, ограниченное число итераций с диагностикой несходимости. Vf красного 2.0, жёлтого 2.1, зелёного 2.2, синего/белого 3.0 В — исключительно из JSON. ERC, DC и калькулятор используют общие данные и явные переопределения экземпляра.
- Для произвольного цвета одиночного LED выбирается ближайший RGB-профиль библиотеки. Для RGB назначение R/G/B→профиль задано JSON. Общий анод/катод учитывается.
- Потенциометр — два сопротивления; нулевой участок в крайних положениях задаётся идеальным источником 0 В без деления на ноль.
- LDR — логарифмическая интерполяция между сопротивлениями при 0% и 100%. NTC — Beta-модель с R25 и температурой в K. Начальные R25=10 kΩ, Beta=3950 K и LDR 1 kΩ/1 MΩ являются параметрами выбранных учебных моделей в JSON, доступны для изменения.
- Острова решаются независимо относительно одной земли каждого острова. Плавающий остров не получает выдуманный ноль; неизвестные напряжения представлены null. Нет временной симуляции.
- VIN без заданного напряжения не считается автоматически источником 5 В. Остальные элементы перечисляются как неподдерживаемые и исключаются из DC.
- Для идеальных замыканий после объединения узлов отдельный ток контакта не определяется. Токи одинаковых параллельных идеальных источников неоднозначны и возвращаются без численного значения. Противоречивые источники/вырожденная матрица дают диагностику.
- Выводятся напряжения узлов, токи и мощность ветвей, предупреждения о превышении тока LED и мощности резистора 0.25 Вт. Подписи напряжений включаются переключателем. Любое завершённое изменение сбрасывает результаты и помечает их устаревшими.

Параметры LED/LDR/NTC редактируются только у соответствующих компонентов; пустое поле означает JSON по умолчанию. Кнопка/реле имеют статическое положение в свойствах, без нажатий на рисунок и анимации. Явные параметры и будущие роли сохраняются в .circ, копируются и участвуют в Undo/Redo. Старые .circ версии 1 продолжают открываться с исходными значениями по умолчанию.

## Архитектура и проверки

Core — net8.0, без WPF, System.Windows и ViewModels. INetlistBuilder, IErcService, IDcSolver и новые UI-сервисы зарегистрированы через интерфейсы в DI. Данные читаются IElectricalLibraryRepository/JsonElectricalLibraryRepository. ViewModel не создают окна, не используют MessageBox/Dispatcher; таймер находится в реализации IDebounceService. Code-behind новых Views содержит только InitializeComponent. Один тип на файл, максимальный CS/XAML-файл — 268 строк.

Debug и Release: dotnet build — 0 ошибок/предупреждений; dotnet test — 329/329. Проверены все ERC-правила, топология/канал/шины, внутренние замыкания, отложенный пересчёт, делитель, ток LED по ручной формуле (5−2)/(220+10), RGB-профили, потенциометр в трёх положениях, LDR/NTC, плавающие/вырожденные цепи, перегрузки, сохранение параметров и сброс результатов. WPF-проверка рисует новые панели, калькулятор и оба вида с результатами. В работающем окне проверены автопроверка питания добавленного зуммера, подсветка выводов, окно калькулятора и результат 5 В / 1 kΩ → 5 мА, 25 мВт.

## Ручная проверка

1. Запустить `dotnet run --project CircuitEditor.App`. Добавить дисплей/датчик/серво без проводов: после задержки появляются предупреждения питания. Нажать строку — камера перемещается к выводу. Проверить фильтр и счётчики.
2. Добавить Arduino Uno/ESP32 без подключений: предупреждений об обязательном питании их выводов нет. Соединить 5V и 3V3 одной Uno — SOURCE_CONFLICT; Undo убирает ошибку.
3. Соединить питание с землёй — SUPPLY_SHORT, для батареи также BATTERY_SHORT. Соединить 5V Uno с GPIO ESP32 — ESP_OVERVOLTAGE. Два I2C-модуля с одинаковыми адресами подключить к общей SDA/SCL — конфликт; смена адреса или разрыв одной линии его устраняет.
4. Собрать батарея (5 В) → резистор 220 Ω → красный LED → минус. ERC не должен сообщать об отсутствии резистора. Шунтировать резистор — предупреждение возвращается. В «Схеме» проверить автоматические линии, переместить символ: макет не перемещается.
5. «Расчёт DC» → «Рассчитать цепь». Для LED с Rd=10 Ω ожидается I=3/230≈13.043 мА. Включить подписи напряжений. Сменить цвет LED на синий — результаты устаревают; после пересчёта I=2/230≈8.696 мА.
6. Проверить делитель из двух 1 kΩ на 5 В: средний узел 2.5 В, ток 2.5 мА. Для потенциометра проверить крайние положения. Изменить освещённость LDR и температуру NTC, пересчитать.
7. Добавить неподдерживаемый дисплей или конденсатор: в результате есть явное сообщение об исключении. Изолированный резистор даёт диагностику плавающего острова; КЗ источника не приводит к падению.
8. «Схема» → «Калькулятор»: закон Ома (ровно два поля), делитель, выбор цвета LED/ряда, преобразование полос в обе стороны. Проверить неверные единицы и пустой ввод.
9. У LED/LDR/NTC изменить параметры модели, применить, проверить Undo/Redo и сохранение/открытие .circ. Пустое поле возвращает значение из JSON.

Проверочный макет, открытый при ручной проверке, сохранён в `%TEMP%/CircuitEditor-stage5-ui-backup.circ` перед закрытием приложения для сборки.
