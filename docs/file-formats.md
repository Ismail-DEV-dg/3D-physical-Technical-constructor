# Форматы проекта и микросхемы

## .circ

Текущий `schemaVersion` равен 4, `libraryVersion` равен `"1"`. Штатные корпуса, детали и breadboard определяются по ID. Для пользовательских микросхем сохраняются объявления в `embeddedChips`, экземпляры указывают ID и ревизию. История операций, модельное время и измерения в документ не входят.

| Поле | Назначение |
|---|---|
| components, counters | Детали, обозначения, значения и счётчики после удаления |
| mockup, schematic | Независимые размещения в миллиметрах и DIP |
| breadboards, bindings | Экземпляр платы и привязки контактов к отверстиям |
| wires | Физические концы по устойчивым ID, цвет, точки изгиба, необязательный флаг `isStraight` |
| mockupNotes | Необязательные текстовые подписи с координатами в миллиметрах |
| view | Открытый режим и параметры камеры |
| sketch | Текст, семейство платы, имя и при необходимости ID экземпляра платы |
| simulationSetup | Выбранный сценарий и расположение приборов |
| embeddedChips | Встроенные определения по ID и ревизии |

Для перемычки без `isStraight` используется плавная интерполяция.

Разветвитель хранит число выходных гнёзд в необязательном поле `splitterOutputs` экземпляра. Значение от 2 до 8. При отсутствии поля у разветвителя три выхода. Концы перемычек указывают на `IN` или `OUT1`…`OUT8`. Указанное гнездо должно существовать при выбранном числе выходов.

Файлы `.circ` v4 из предыдущей сборки читаются новым редактором без добавления обязательных полей. Открытие проектов с новым типом компонента в старой сборке зависит от наличия этого компонента в её библиотеке.

Полный свёрстанный JSON с платой, деталями, перемычками и скетчем: [uno-blink.circ](../Samples/uno-blink.circ). Пример проекта со встроенной микросхемой: [decoder.circ](../Samples/decoder.circ).

Миграции выполняет JsonProjectRepository: 1→2 дополняет документ пустым скетчем, 2→3 — настройками симуляции, 3→4 — списком встроенных микросхем. Будущая версия отклоняется с номером файла и поддерживаемой версией. Если `libraryVersion` пропущена, применяется текущая версия и показывается предупреждение; библиотечные ID всё равно проверяются. При несовпадении локальной и встроенной ревизий приложение предлагает выбор и проверяет проект перед заменой открытой модели.

## .chip

Независимый `schemaVersion: 1`. В объекте `definition` хранятся `id`, `definitionVersion`, имя, описание, DIP-корпус, семейство, список выводов, задержка распространения и `behavior`. Поведение — секционная таблица истинности или граф блоков. Файлы библиотеки хранятся в профиле пользователя.

Пример определения с таблицей: [DECODER-2](../CircuitEditor.Infrastructure/Data/Chips/decoder-2.json). При экспорте .chip это определение вкладывается в `{"schemaVersion":1,"definition":{…}}`. Примеры графов находятся в [каталоге шаблонов](../CircuitEditor.Infrastructure/Data/Chips).

## Экспорт

PNG — оба плоских представления или вид 3D с текущей камерой. SVG — условная схема. OBJ/MTL — геометрия 3D и материалы. BOM — CSV с разделителем `;` и UTF-8 BOM. В конструкторе микросхем распиновка выгружается в PNG или Markdown, таблица — в CSV или Markdown.
