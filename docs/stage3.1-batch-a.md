# Этап 3.1 — реалистичные компоненты, пачка A

Все изображения — WPF DrawingContext: векторные примитивы, градиенты и встроенный шрифт. Внешних картинок или 3D-моделей нет. Геометрия контактов и габариты в миллиметрах находятся в Infrastructure/Data/footprints.json, читаются существующим репозиторием. Шаг контактов 2,54 мм; масштаб остаётся в PhysicalSettings.

Корпуса не универсальны для любых клонов. Порядок выводов выбранных вариантов записан в JSON. Ряд контактов дисплея при вставке вдоль колонки breadboard подключается к отдельным группам; поперечная посадка однорядного разъёма способна электрически объединить сигналы, как на настоящей плате. ERC в этом этапе не добавлялся.

## Ручная проверка

1. Запуск: `dotnet run --project CircuitEditor.App`.
2. Поиск «Arduino Nano» → перенести карточку первым контактом в B2. Должно появиться сообщение «все контакты вставлены»; оба ряда лежат по разные стороны центрального канала. Наведение на контакты показывает физический номер и электрическое имя.
3. Удалить Nano; проверить ESP32 из A2. GPIO34–39 (выведенные 34/35/36/39) подсвечены голубым, тултип поясняет input only; EN поясняет active-low. Плата также свободно размещается рядом с breadboard.
4. Для каждого дисплея сначала перенести компонент на свободное поле рядом с платой, повернуть R и затем перетащить первым контактом в отверстие из таблицы. После каждого примера удалить компонент, освобождая отверстия.
5. Попробовать вставить поверх занятого контакта и с несовпадающим шагом. Отказ не должен оставлять частично занятых отверстий; при перемещении сохраняется прежнее размещение.
6. Переключить Neon Dark / Light Tech, проверить подписи и контраст. Масштабировать колесом: все элементы остаются векторными. «Схема» показывает те же компоненты, её координаты независимы.

## Автоматические проверки

- `dotnet build CircuitEditor.sln`; `dotnet test CircuitEditor.sln --no-build --no-restore`.
- Аналогично Release. Итог: 165 тестов; 0 ошибок и предупреждений сборки.
- Все шесть вставок: число контактов, уникальные отверстия, отсутствие объединения разных сигналов одной группой, полное соответствие открытым электрическим выводам.
- Отказ при смещении и занятом последнем контакте — атомарный, JSON-снимок проекта не меняется.
- Двойные RESET/COM, отсутствие GPIO0 в разъёме ESP32, количество оставшихся заглушек.
- Рендер всех шести моделей при 0/90/180/270° в обеих темах, проверка непустого рисунка и подсказок каждого физического контакта.
- Для контрольных PNG тестов можно установить `CIRCUIT_EDITOR_VISUAL_CHECK` в каталог вывода: BatchAPresentationChecks сохраняет обзор в обеих темах. Эти PNG — только проверочные артефакты, приложение их не использует.

## Готовые и оставшиеся

- Добавлены: Arduino Nano, ESP32 DevKit, LCD 16×2, LCD 16×2 I2C, OLED SSD1306, 7-сегментный индикатор.
- Ранее готовы: Arduino Uno, резистор, светодиод, кнопка. Breadboard также готова отдельно от библиотеки компонентов.
- Остались 17 заглушек: конденсатор, катушка, потенциометр, RGB-светодиод, зуммер, переключатель, батарея, фоторезистор, термистор, DHT11, DHT22, HC-SR04, PIR, сервопривод, реле, транзистор NPN, диод (гибкая контактная геометрия диода уже есть).
- Нажатия, анимации, симуляция, провода, история и файловые команды не добавлялись.
