# Производительность этапа 10

Windows 11 Pro, Ryzen 5 8400F, RTX 3070, 32 ГиБ. Окно 1184×761 DIP, 96 DPI, WPF Render Tier 2, Debug. Стенд строит 109 деталей и 200 перемычек и открывает временный .circ через репозиторий. Ввод двигает Uno, а 3D-стенд вращает камеру по воспроизводимой траектории.

| Метрика | До кэша | После кэша, тот же стенд | Итоговый стенд |
|---|---:|---:|---:|
| Открытие .circ и первый макет, мс | 315,3 | 330,9 | 331,4 |
| Перетаскивание, кадров/с | 29,4 | 29,6 | 66,2 |
| Обработка ввода и WPF layout, p95 мс | 2,67 | 2,19 | 2,12 |
| Макет во время симуляции, кадров/с | 52,6 | 56,1 | 54,0 |
| 3D вращение без симуляции, кадров/с | 97,2 | 98,8 | 97,6 |
| 3D вращение с симуляцией, кадров/с | 93,9 | 92,8 | 91,2 |
| 3D первая сборка без / с симуляцией, мс | 190,3 / 76,9 | 190,9 / 77,1 | 193,8 / 72,7 |
| Обновление одного 3D-узла без / с симуляцией, мс | 9,5 / 12,9 | 9,5 / 15,4 | 10,1 / 15,0 |

Кэш переиспользует физические границы и замороженные преобразования неподвижных деталей. На прежней методике выигрыш p95 составил около 18%. Прежний генератор мыши посылал событие в обратном вызове кадра WPF и влиял на его же частоту. В итоговом стенде мышь и отрисовка планируются независимо. Разницу между 29,6 и 66,2 FPS нельзя приписать кэшу. p95 включает вызов команды и обновление WPF layout, без задержек устройств ввода и вывода. Агрегирование всех объектов 3D в один набор по материалам не понадобилось.

| Память после сборки мусора | Управляемая, МиБ | Private bytes, МиБ |
|---|---:|---:|
| После прогрева | 8,39 | 115,59 |
| 20 открытий и закрытий | 8,47 | 124,77 |
| 50 запусков и остановок | 8,53 | 124,38 |
| 50 переключений Макет ↔ 3D | 9,16 | 133,71 |

Из 50 выгруженных представлений 3D осталось 0 по слабым ссылкам. Замер одного прогона показывает объём удерживаемых объектов, но сам по себе не доказывает отсутствие любого роста памяти.

```powershell
dotnet run --project CircuitEditor.App -- --benchmark-stage10 "$env:TEMP/workbench.json"
dotnet run --project CircuitEditor.App -- --benchmark-3d "$env:TEMP/three-d.json"
```

Первый стенд рядом с отчётом создаёт одноимённый .circ. Используйте отдельный путь, не совпадающий с рабочим проектом.
